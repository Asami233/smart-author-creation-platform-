## 1. 产品定位重新确认

智能作者创作平台首先是一款供个人中文网文作者持续写作的桌面浏览器工作台。核心价值依次是：稿件可靠保存、长篇结构清楚、资料容易查找、AI 在明确授权范围内辅助创作。

主要用户场景：

1. 开始一部作品：填写作品信息、建立卷章，立即获得空白可写正文。
2. 每日写作：恢复上次位置，持续输入、改标题、切章，明确知道内容是否保存成功。
3. 规划长篇：维护大纲、角色、世界观、时间线，将资料关联到章节。
4. 遇到卡文：选择参考资料和需求，调用真实模型；先读预览，再决定是否采纳。
5. 修改与交付：比较历史内容、恢复版本、找回误删章节、导出稿件和备份。

当前产品边界：

- 服务个人作者、多部作品；不增加团队协作、社区、支付、排行榜。
- 本地开发版本的作品存储在本机服务所用的数据库。存在邮箱账号不等于已实现云同步、多端离线合并或生产邮件投递。
- AI 调用会把用户选中的内容发送给配置的外部服务商；应用可控制发送范围，不能代替服务商承诺“永不训练”。
- 继续沿用仓库现有 React / TypeScript / vinext-Vite / D1 / Drizzle 实现，本轮不切换框架或数据库。
- 富文本是已确定方向。当前实现仍是原生 contentEditable；专业编辑器迁移需要单独处理旧稿格式与回滚，不能混入美化任务。

## 4. 对 Gemini 后续需求的产品结论

### 分卷管理

- 保留新建分卷、主动折叠、空分卷加章能力，选中章节所在卷也允许用户折叠。
- 删除分卷的现有后端行为已经明确：server/services/works.ts 的 deleteVolume 把章 volume_id 置空，将卷级大纲改为作品级，再删除卷记录。不会随卷删除正文，也不会自动移到第一卷。
- Gemini 应展示“未分卷”分组，并在删除确认中说明正文保留、卷级大纲转作品级。分卷记录本身不宣称可从回收站恢复。
- 新增整书分卷重排列入 G1。建议沿用完整 ID 列表与归属校验；路径和请求格式须由 Codex 在 contracts 和正式交接中确定后才能接入。
- 跨卷移动章节需要明确目标位置、未分卷、源/目标列表刷新及失败回滚；列入 G1 范围评审。已有单章接口可满足时优先复用，批量接口不提前承诺。

### AI 创作能力

- 续写、润色、大纲和人物/情节讨论优先形成同一套“选择范围→生成→预览→采纳”的体验。
- 前后文矛盾检查先限于明确选中的资料，输出“疑点、引用依据、建议”，不宣称能证明全书无矛盾；放在流式基础稳定后的增强批次。
- 当前 runAiPreview 虽然名称沿用旧版，内部已调用 generateAiContent。不得只凭名字认定是假生成并删除。
- AI 预览必须绑定生成时的作品、章节及基准版本；生成期间切章或正文变化后，采纳需要重新确认目标，不能把旧结果写到新章节。
- 取消优先中断服务端上游请求并保留可复制的部分结果；不能承诺供应商不产生费用。失败重试由用户触发，避免自动重复付费请求。

### 写作目标与真实统计

- 首先保证“当前作品总字数”和“当天正向写作字数”口径明确。总字数、目标字数、当天产出是三个不同指标。
- 默认作品级日目标；未来账号总览通过服务端汇总。上海日期作为本阶段日界线。
- 每日净增、历史累计趋势需要后端事件记录，覆盖编辑、删除、恢复、导入等路径。上线前的历史留空/标记不完整，不能从只增不减的 wordsWritten 倒推出净增。
- “目标 0”按该字段正式契约解释为不设目标；不得除以零或显示已完成无限目标。

## 8. 每轮交付规则

1. 后端先交正式契约、兼容性、迁移说明、测试与交接文档，再由 Gemini 接新能力。
2. UI 优化先列修改页面和复用规范，再实现。每轮最多一项主要流程改造，避免视觉修改和编辑器替换同时进行。
3. 前后端交接区分“代码完成”“自身验证通过”“联合验收通过”；不能仅凭编译通过勾选业务验收。
4. 每过 G0～G5 任一门槛，向项目所有者报告已通过依据、遗留限制和下一工作包；未过则保留明确问题，不按日历强行推进。
5. 本轮最终交付是本规划、UI 规范和 Gemini 工作提示词；没有开始后续代码开发。
