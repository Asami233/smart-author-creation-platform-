# 后端实施路线与完成状态

本文只描述 Codex 负责的后端范围。页面、组件、TipTap 编辑器和前端状态由 Gemini 负责。

> 当前跨端优先级与后续迭代以 [`DEVELOPMENT_PLAN.md`](./DEVELOPMENT_PLAN.md) 为准。每次后端交付说明见 [`handoffs/README.md`](./handoffs/README.md)。

## 阶段 A：写作核心与本地持久化

状态：已实现，等待前端接入。

- D1/SQLite 正式数据模型
- 作品、分卷、章节 CRUD
- 章节移动、排序和软删除
- 章节修订号与乐观并发控制
- 自动保存所需的幂等更新接口
- 写作目标、每日增量、总字数和连续写作统计
- 作品内章节、角色、设定和大纲搜索

验收重点：前端保存时携带 `expectedRevision`；冲突时必须让用户刷新或选择版本，不能静默覆盖。

## 阶段 B：大纲与设定系统

状态：已实现，等待前端接入。

- 作品/分卷/章节级大纲
- 角色卡与扩展元数据
- 地点、势力、能力体系、物品和自定义世界观条目
- 时间线事件、故事时间和参与角色
- 章节与大纲、角色、设定、时间线的双向关联基础

验收重点：所有设定对象都必须属于当前作品，跨作品关联会被后端拒绝。

## 阶段 C：AI 安全代理

状态：已实现服务端能力，真实调用需要本地配置 `APP_ENCRYPTION_KEY` 和用户保存模型配置。

- OpenAI-compatible `/chat/completions` 代理
- OpenAI、DeepSeek 等 HTTPS 兼容地址
- 续写、改写、润色、大纲、头脑风暴和一致性检查
- 用户显式上下文范围；不从数据库自动拼接整部作品
- API Key AES-GCM 加密保存
- 私网/本机地址阻断，降低 SSRF 风险
- 60 秒超时、供应商错误映射、每日请求上限和 token 统计
- 输出仅返回建议，不直接修改正文

验收重点：前端先保存 AI 设置，再由同源后端发起模型请求；浏览器不得直接请求模型供应商。

## 阶段 D：历史版本与导出

状态：已实现后端能力，等待前端接入。

- 按时间或字数变化创建自动快照
- 手动命名版本
- 查看版本内容
- 恢复前自动保留当前版本
- TXT 网文格式导出
- DOCX 中文样式导出
- PDF 中文 CID 字体导出
- 全书或指定章节导出

验收重点：恢复历史版本不会删除任何现有版本；导出的章节顺序与作品目录一致。

## 阶段 E：邮箱账号与会话

状态：邮箱认证已实现；跨设备同步暂缓。

- 邮箱注册与验证码验证
- 密码登录与邮箱验证码登录
- 找回密码、修改密码和会话撤销
- HttpOnly Cookie、密码哈希、限流与登录锁定
- 用户资料与作品数据隔离
- 本地开发保留 `local-author` 兼容模式，部署环境要求登录

验收重点：生产环境需要真实邮件服务；前端不得用本地用户缓存替代服务端会话判断。

## 阶段 F：数据安全与多作品工作台

状态：后端已实现，等待前端完整接入。

- 完整备份、导入预检与恢复
- 作品和章节回收站
- 存储摘要
- 多小说列表、创建与当前作品持久状态
- 新作品自动创建第一卷和第一章

验收重点：切换作品后不得混用章节；导入与恢复失败不得破坏现有数据。

## 阶段 G：真实 AI 配置

状态：后端已实现基础连接，流式生成待开发。

- 从供应商真实 `/models` 接口发现模型
- 真实 Chat Completions 连接测试
- 服务端加密保存和脱敏读取 API Key
- 已保存配置允许只更新地址或模型
- 真实生成、错误映射、限流和用量记录

验收重点：删除所有前端固定建议；AI 输出只预览，用户确认后才写入正文。

## 下一后端重点

1. 本地 `local-author` 作品安全认领到邮箱账号。
2. AI 流式生成、主动取消和上下文预算预览。
3. TipTap 内容格式版本与长章节保存策略。
4. 会话设备管理、账号数据导出和注销清除。

## 后端质量门槛

- 数据结构变更必须生成新的 Drizzle 迁移，不改写已应用迁移。
- API 只返回统一的 `{ data }` 或 `{ error }` 格式。
- 所有输入经 Zod 校验。
- 数据访问必须校验作品归属。
- AI 密钥和正文不得写入日志。
- 后端测试通过后才能合并到主分支。
- 完成后必须写 `docs/handoffs/` 交接文档并更新索引。
