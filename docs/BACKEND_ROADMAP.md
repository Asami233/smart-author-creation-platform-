# 后端实施路线与完成状态

本文只描述 Codex 负责的后端范围。页面、组件、TipTap 编辑器和前端状态由 Gemini 负责。

## 阶段 A：写作核心与本地持久化

状态：已实现，等待前端接入。

- D1/SQLite 正式数据模型
- 作品、分卷、章节 CRUD
- 章节移动、排序和软删除
- 章节修订号与乐观并发控制
- 自动保存所需的幂等更新接口
- 写作目标、每日增量、总字数和连续写作统计
- 作品内章节、角色、设定和大纲搜索

验收重点：前端保存时携带 `expectedRevision`；冲突时必须让用户刷新或选择版本，不能静默覆盖。

## 阶段 B：大纲与设定系统

状态：已实现，等待前端接入。

- 作品/分卷/章节级大纲
- 角色卡与扩展元数据
- 地点、势力、能力体系、物品和自定义世界观条目
- 时间线事件、故事时间和参与角色
- 章节与大纲、角色、设定、时间线的双向关联基础

验收重点：所有设定对象都必须属于当前作品，跨作品关联会被后端拒绝。

## 阶段 C：AI 安全代理

状态：已实现服务端能力，真实调用需要本地配置 `APP_ENCRYPTION_KEY` 和用户保存模型配置。

- OpenAI-compatible `/chat/completions` 代理
- OpenAI、DeepSeek 等 HTTPS 兼容地址
- 续写、改写、润色、大纲、头脑风暴和一致性检查
- 用户显式上下文范围；不从数据库自动拼接整部作品
- API Key AES-GCM 加密保存
- 私网/本机地址阻断，降低 SSRF 风险
- 60 秒超时、供应商错误映射、每日请求上限和 token 统计
- 输出仅返回建议，不直接修改正文

验收重点：前端先保存 AI 设置，再由同源后端发起模型请求；浏览器不得直接请求模型供应商。

## 阶段 D：历史版本与导出

状态：已实现后端能力，等待前端接入。

- 按时间或字数变化创建自动快照
- 手动命名版本
- 查看版本内容
- 恢复前自动保留当前版本
- TXT 网文格式导出
- DOCX 中文样式导出
- PDF 中文 CID 字体导出
- 全书或指定章节导出

验收重点：恢复历史版本不会删除任何现有版本；导出的章节顺序与作品目录一致。

## 阶段 E：账号与云同步

状态：暂缓。

当前所有请求固定归属本地用户 `local-author`。进入 M6 后再替换为真实身份、云端数据隔离、离线同步和冲突处理。本阶段不会提前加入伪登录。

## 后端质量门槛

- 数据结构变更必须生成新的 Drizzle 迁移，不改写已应用迁移。
- API 只返回统一的 `{ data }` 或 `{ error }` 格式。
- 所有输入经 Zod 校验。
- 数据访问必须校验作品归属。
- AI 密钥和正文不得写入日志。
- 后端测试通过后才能合并到主分支。
