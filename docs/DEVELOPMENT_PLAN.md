# 智能作者创作平台：后续开发计划

更新时间：2026-09-26

本周最终状态：[五个有效工作日计划](./WEEKLY_PLAN_2026-09-23.md)与[第 5 天结项](./handoffs/2026-09-26-fullstack-week-day5-complete.md)。G0/G1 已于第 3 天正式放行，迭代 3 的真实 AI 流式预览、停止、显式上下文预算、兼容处理和用量语义已于第 5 天通过联验。**本周已结项；下一周按迭代 4 的账号数据迁移与安全门槛另行启动，不自动执行数据认领、注销或发布。**第 1～4 天的详细证据保留在交接索引中。

当前执行补充见 [产品复盘、阶段预验收与周期](./PRODUCT_REVIEW_AND_ROADMAP_2026-09-23.md)、[字体与界面规范](./UI_STYLE_GUIDE.md) 和 [Gemini 本轮提示词](./handoffs/2026-09-23-product-review-ui-roadmap.md)。下列迭代编号保持不变；已接入能力按补充文档验收，不重复开发。G0/G1 是迭代 1/2 的收口门槛，不是新增业务阶段。

## 一、当前判断

后端基础能力已经覆盖作品、卷章、设定资料、版本、导出、备份、邮箱认证、真实 AI 代理和当前作品切换。迭代 1/2 的 G0/G1 验收已收口，迭代 3 的基础 AI 创作闭环已通过本周工作包验收。下一阶段重点是访客作品认领与账号安全，仍须区分本机验证和正式邮件/部署环境验收。

因此后续顺序确定为：

`保存与隔离验收 → 设定/版本/导出闭环与 UI 统一 → AI 体验 → 账号与数据恢复 → 编辑器与统计 → 发布准备`

本期不新增社区、付费、多人协作或复杂运营后台。

## 二、迭代 1：正式工作台接入（P0）

目标：用户登录后可以创建、切换并持续编辑多部真实小说，页面不再依赖固定《长夜行》数据。

### Codex 后端

- 保持 `/api/workspace`、`/api/works`、卷章接口稳定。
- 修复前端联调发现的契约缺口。
- 补充作品归属、跨作品章节选择和并发保存的回归测试。
- 必要时增加工作台聚合接口，但不为页面样式定制数据库结构。

### Codex 前端

- 制作总体作品工作台、作品卡片、创建小说弹窗和作品切换器。
- 用 `/api/workspace` 替换固定作品标题和固定章节数组。
- 创建作品后直接进入后端生成的第一卷、第一章。
- 章节保存携带 `expectedRevision`，正确处理 `409 CONFLICT`。
- 完成空状态、加载状态、接口错误和无作品状态。
- 删除正式路径中的静默 mock 回退；演示数据只能存在于明确标记的演示模式。

### 联合验收

- 创建两部小说后可以来回切换，刷新页面仍保持当前作品。
- 两部小说的章节、字数和设定完全隔离。
- 连续编辑、刷新、切章不会丢失正文。
- 未登录的部署环境无法读取他人作品。

## 三、迭代 2：设定、历史版本与导出闭环（P0）

目标：把已经存在的后端能力接入真实页面，形成可长期写作的基本产品。

### Codex 后端

- 稳定大纲、角色、世界观、时间线和章节关联契约。
- 校验版本恢复、软删除、回收站和三种导出格式。
- 补齐前端需要但契约中缺失的分页或摘要字段。
- 已交付章节跨卷移动/卷内排序安全增强，沿用 `POST /api/works/:workId/chapters/reorder`；目标完整列表 + `expectedRevisions`，不新增重叠接口。

### Codex 前端

- 大纲、角色、世界观和时间线全部改用正式接口。
- 完成章节与设定关联的查看、添加和移除。
- 接入自动版本、手动版本、版本预览与恢复确认。
- 接入 TXT、DOCX、PDF 真正下载，移除前端伪造文件。
- 接入回收站、恢复作品和恢复章节。
- 下一工作包：章节上移/下移、移动到分卷/未分卷，保存门禁、修订号同步及 409 保稿；拖拽可作为后续增强，不能成为唯一入口。

### 当前一周安排（2026-09-23 起）

按 [五个有效工作日计划](./WEEKLY_PLAN_2026-09-23.md) 执行。第 1 天 Q01 真实页面复验及测试已完成；第 2 天收口 Q02 剩余安全路径；第 3 天补 G0/G1 导出、恢复、多尺寸目视验收。通过门槛后，第 4、5 天再开展 AI 流式与上下文预算后端实现及前端接入。失败项顺延，不能按日历强行放行。

### 联合验收

- 设定对象不可跨作品串联。
- 恢复旧版本前自动保存当前版本。
- 导出文件的标题、卷章顺序、正文和中文排版正确。
- 删除内容可以从回收站恢复。

## 四、迭代 3：真实 AI 创作体验（P0）

目标：完全移除固定 AI 建议，让每次输出都来自用户配置的真实模型，并保持用户对上下文和正文修改的控制权。

### Codex 后端

- 保持真实模型发现、连接测试和加密配置接口稳定。
- 增加流式生成与用户主动取消能力。
- 增加请求前上下文摘要、字符/token 预算和超限提示。
- 为不同 OpenAI-compatible 供应商增加能力探测和兼容字段处理。
- 保留安全地址校验、超时、限流和用量统计。

### Codex 前端

- 检查实际生成调用，清除仍存在的假结果；当前同名 `runAiPreview` 已调用真实接口，不按函数名机械删除。
- 接入真实模型列表、连接测试、加密保存与删除配置。
- 让用户明确勾选正文、大纲、角色、世界观和时间线上下文。
- 展示即将发送的数据范围和大致长度。
- AI 输出只进入预览区；必须点击“采纳”才写入正文。
- 支持停止生成、重试、复制、舍弃和采纳。

### 联合验收

- 浏览器网络请求中不出现对模型供应商的直接访问。
- 浏览器存储和前端日志中没有 API Key。
- 未配置、密钥错误、模型不存在、超时、限流均有明确提示。
- AI 不会未经确认覆盖正文。

## 五、迭代 4：账号数据迁移与安全（P1）

目标：解决早期 `local-author` 数据与正式邮箱账号之间的迁移，并提高数据可恢复性。

### Codex 后端

- 增加本地访客作品认领流程：预览、确认、备份、迁移、幂等重试。
- 增加账号注销、数据导出和服务端数据清理接口。
- 增加会话列表、撤销指定设备、过期会话清理。
- 完善备份导入冲突策略、导入预检和失败回滚。
- 完成生产邮件服务配置检查。

### Codex 前端

- 增加“发现本地旧作品”的迁移向导。
- 展示迁移范围、备份结果和不可逆风险。
- 增加设备会话管理、注销账号和导出全部数据页面。
- 完成备份导入预检结果与冲突选择界面。

### 联合验收

- 迁移失败不会破坏原作品。
- 重复执行认领不会产生重复作品。
- 重置密码和注销账号会按规则撤销会话。
- 完整备份可以在空数据库恢复。

## 六、迭代 5：编辑器与写作效率（P1）

目标：让长篇、高频写作达到稳定可用，而不只是功能可点。

### Codex 后端

- 明确 TipTap 文档存储格式和向后兼容策略。
- 增加内容格式版本字段和迁移器。
- 优化长章节保存、搜索、版本快照和统计性能。
- 增加幂等请求与更清晰的冲突详情。

### Codex 前端

- 用 TipTap 替换原生 `contentEditable`。
- 实现快捷键、专注模式、查找替换、章节跳转和离开保护。
- 自动保存采用防抖、状态反馈和失败重试。
- 增加超长章节性能测试和编辑器回归测试。

### 联合验收

- 10 万字级章节仍可编辑和保存。
- 网络中断、重复提交和修订冲突不会静默丢稿。
- 粘贴富文本不会引入危险脚本或破坏排版。

## 七、迭代 6：发布准备（P1）

目标：从本地开发版本推进到可部署、可监控、可回滚的测试版本。

- 确定 Cloudflare/D1 的正式环境、域名和邮件发件域名。
- 分离开发、预发布和生产环境变量。
- 建立数据库迁移、备份、回滚和恢复演练。
- 增加关键 API 日志、错误追踪和匿名性能指标，禁止记录正文和密钥。
- 建立 Playwright 核心流程：注册、创建作品、写作、AI、版本、导出、备份。
- 完成无障碍、浏览器兼容性和桌面分辨率测试。

## 八、暂缓范围

- 多人实时协作与权限角色
- 社区、排行榜、作者广场
- 订阅、支付、计费和模型额度售卖
- 原生移动端与桌面客户端
- 自动把整部作品发送给 AI
- 多设备离线合并；在单设备云端版本稳定后再设计

## 九、每轮交付规则

每个功能按以下顺序完成：

1. 明确用户流程和验收条件。
2. Codex 先更新 `contracts/**`，再实现后端、迁移和测试。
3. Codex 基于正式契约实现前端，不从数据库内部结构猜测字段。
4. 前端、后端、类型和构建分别通过测试，再进行一次真实浏览器联合验收。
5. Codex 在 `docs/handoffs/` 写交付文档并更新索引，分别说明页面、接口、契约、迁移与兼容性。
6. 未通过联合验收的功能不得标记为完成。

G0 保存与隔离、G1 迭代 2 闭环已于 2026-09-26 放行；迭代 3 的本周 AI 流式、上下文预算、取消与隐私边界也已结项。下一工作包建议按迭代 4 先设计本地访客数据认领的预览、备份、确认和幂等接口，再接账号会话与正式邮件环境验证；是否启动由项目所有者确认。
