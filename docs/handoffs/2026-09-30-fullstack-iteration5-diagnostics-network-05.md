### 测试工具

`scripts/chapter-fault-proxy.mjs` 是独立、仅供测试的 loopback 代理，默认 `5179 → 5178`。必须显式传入合成章节 UUID；只有该章的 GET/PATCH 会被注入，且每次故障仅消费一次。拒绝外部 Host、跨站请求和非本地 Origin，无浏览器控制接口；通过启动终端输入模式：

| 模式 | 行为 |
| --- | --- |
| `none` | 取消尚未触发的故障 |
| `hang-read` / `hang-save` | 不转发目标请求，等待客户端截止（代理自身最长 120 秒） |
| `delay-read` / `delay-save` | 上游完成后延迟响应，最终脚本默认 12 秒 |
| `drop-save-response` | 消费完上游保存响应，再发送不完整 JSON 并断开，让客户端明确遭遇响应丢失 |

仅关闭尚未发送响应的 socket 可能被浏览器传输层透明恢复，不能保证页面见到失败；因此最终工具用响应正文截断使失败可确定复现。代理日志只含模式、状态码和延迟，不记录正文或请求凭据。

## 2. 浏览器长章实测

环境：当前生产构建、Codex 内置 Chromium、本机隔离数据。合成章“十万字千段性能验收”，初始 100,140 个可见字符 / 1,000 段；末尾逐字符输入“长章测量输入一二三四五六七八九十。”5 次，共 85 字。

清空诊断样本后采样；本机本轮值如下：

| 指标 | 样本数 | P50 ms | P95 ms | 最大 ms |
| --- | ---: | ---: | ---: | ---: |
| HTML 序列化 | 85 | 3.10 | 5.00 | 6.80 |
| onUpdate 同步处理（包含序列化） | 85 | 5.10 | 7.10 | 10.80 |
| beforeinput → 双帧回调 | 85 | 16.20 | 23.70 | 30.60 |
| 被观察到的编辑事件（≥16 ms） | 170 | 16.00 | 24.00 | 40.00 |
| 被观察到的页面长任务（≥50 ms） | 0 | — | — | — |

- 输入后 API 确认 100,225 字、修订 v7。后续迟到读取测试追加 9 字并保存至 v8。
- 同步处理和序列化是包含关系，不能相加当作总延迟。
- 双帧回调只是近似指标，**不等于实际按键到像素绘制，也不是 INP**；本轮没有独立 React commit/render 分段测量。
- 事件统计只含被观察器报告的事件，不是所有按键的无偏分布；没有长任务样本不代表没有任何卡顿。
- 这是自动逐字符输入，不是中文输入法 composition 验收；仅单机短时数据，不设通用毫秒承诺。

### 内存观察

JS 堆估计：输入前 17.30 MiB → 输入后 37.76 MiB → 三轮短章/长章往返后 21.69 MiB。采样受到工具、面板、编辑历史与垃圾回收时机影响，没有强制 GC，没有堆对象保留链分析。回落只能作为短时观察，**不能证明没有泄漏**，也不是整个浏览器进程的内存。

有关 API 限制参见 [MDN performance.memory](https://developer.mozilla.org/en-US/docs/Web/API/Performance/memory)、[PerformanceEventTiming](https://developer.mozilla.org/en-US/docs/Web/API/PerformanceEventTiming) 和 [requestAnimationFrame](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame)。

## 3. 真实页面故障验收

隔离库：`.wrangler/day7-acceptance-20260927`；未使用或改动日常 `.wrangler/state`。

故障合成章：`37a0abbc-6525-429a-a052-21a79a786ba2`，标题“复杂网络故障验收”。长章：`4f6a757e-ea89-4492-a4e8-55ae5fb2f224`。

| 场景 | 页面与接口交叉证据 | 结果 |
| --- | --- | --- |
| 保存提交成功，响应正文截断 | 页面显示保存失败和重试，正文保留；直读上游已为 v3；点重试后页面保存成功，仍 v3，快照仍 1 条 | 通过，无重复修订/快照 |
| 保存请求挂起、不转发 | 页面约 15 秒后失败，日志出现 RequestDeadlineError；正文保留；上游仍 v3、没有新后缀；点重试成功 v4 | 通过，释放保存状态 |
| 旧保存响应延迟期间继续输入 | v9 追加“强制先保存甲。”并 Ctrl+S 立即提交，再追加“随后新稿乙。”；工具确认响应延迟 12 秒；当时页面仍 v9 且含两段；最终页面/API 都为 v11 且两段完整 | 通过，旧响应未覆盖新稿 |
| 目标章节读取响应迟到，原章有新输入 | 从长章切短章，等待期间在原长章追加“切章在途继续输入。”；迟到后出现“本次跳转已取消”提示，仍在长章，新稿保存至 v8 | 通过（该次使用代理原 6 秒延迟） |
| 目标章节读取一直挂起 | 保持原章；截止后出现“章节加载失败，当前稿件保持不变”；再次点目标章正常进入 | 通过 |
| 刷新复读与默认诊断关闭 | 不带诊断参数重新加载，选择故障章，完整内容仍在、v11；诊断按钮数为 0 | 通过 |

本轮没有同时覆盖“保存已提交但响应丢失 + 新输入 + 另一窗口写入”的组合，不能将单项通过等同所有排列组合通过。也没有扩大截止到作品目录、结构操作或 AI 请求。
