# 一周第 3 天：G0/G1 真实页面与导出复验

日期：2026-09-26  
方向：Codex → 项目所有者 / Gemini  
结论：**后端与多数页面链路已通过，但第 3 天联合验收尚未完成；G0/G1 暂不放行，迭代 3 的 AI 流式实现顺延。** 本轮没有后端接口、契约或数据库变更。

## 已取得的验收证据

- 在两部一次性测试作品中，真实页面连续输入、自动保存、切章、刷新与切作品后，正文仍正确；第二部作品没有出现第一部的章节或字数。
- 手动创建旧稿快照后继续写作，再从页面恢复旧稿。恢复后正文回到旧稿；版本接口中新增 `restore` 备份，包含恢复前较新的完整正文，证明可以找回。
- 章节和作品经 API 软删除后进入回收站；实际页面分别点击“恢复章节”“恢复作品”成功。页面中的删除确认弹窗使本次浏览器自动化停在原生 `window.confirm`，因此**删除按钮的整条 UI 链路还需 Gemini 在真实浏览器手动复验**；不能把 API 删除成功冒充 UI 删除通过。
- 页面三个导出入口分别请求服务端 TXT、DOCX、PDF 并返回 `200`。另下载文件实际检查：TXT 文本与 DOCX 文档 XML 包含正确的作品标题、卷章顺序和中文正文；PDF 为 A4 单页，渲染图片目视内容正确。PDF 当前缺少可用的中文文字映射，`pdfplumber` 提取出的中文乱码；视觉阅读通过，但“可搜索/复制中文的 PDF”应列为后端质量后续项，不能宣称已实现。本轮未留下不完整的 PDF 修补代码。
- 后端 43/43 测试、前端 27/27 测试、知识/版本冒烟测试、TypeScript 检查和生产构建通过。构建仅有既有的 vinext 路由分类与大 chunk 提示。
- 测试作品按精确 ID、所有者与标题核对后清理，原先活动作品/章节选择已恢复；用户现有作品未修改。临时导出文件与开发服务已清理。

## 尚未通过的页面与布局项

1. 归档作品的回收站日期显示为 `Invalid Date`。`components/workbench/trash-dialog.tsx` 使用 `w.deletedAt`，但正式契约 `contracts/data-safety.ts` 与后端响应字段为 `archivedAt`。Gemini 应在其责任区修复，并为缺失/无效日期提供可读占位。
2. `components/workbench/version-history-dialog.tsx` 的“恢复至此版本”点击后立即调用恢复接口，没有二次确认。计划要求版本预览与恢复确认；请展示要恢复的快照和会影响当前正文的提示，允许取消，保留现有保存冲刷与 `409` 保稿行为。
3. 1366×768 页面中 AI 侧栏“配置”按钮右缘约超出视口 19 px，“生成建议”约超出 6 px；1440×900 分别约超出 14 px、1 px；1920 宽下未见裁切。编辑区仍可写，但桌面适配未过。请 Gemini 修复右侧容器和按钮的宽度/溢出，不靠整页横向滚动。浏览器自动化快捷键未能真实改变缩放比例，**125% / 150% 实际缩放未验收**，需另行复测。
4. 原生删除确认触发了本次自动化连接挂起，无法据此判定产品缺陷；需人工或可处理系统弹窗的浏览器流程补齐“页面删除 → 回收站 → 页面恢复”。

以上 1、2、3 是前端责任区；Codex 不修改页面。PDF 中文文字提取是后端责任区的质量改进，作为后续独立任务，不阻止当前“实际打开与视觉内容正确”的导出验收；如产品所有者把可复制文字列为当前门槛，应重新安排后端修复与复验。
