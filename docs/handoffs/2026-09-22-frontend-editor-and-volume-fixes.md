## 1. 本次前端交付概述

针对用户最新反馈的 5 项明确需求与 Bug，前端已全部完成修复与交互优化：

1. **当前激活章节所在卷的折叠支持**（“在已经点击的章节卷里，也可以折叠，这点要分清”）：排查并移除了依赖中的自动反向展开副作用，使用户对分卷的折叠与展开拥有完全的自主控制权，当前正在阅读/编辑的卷亦可自由折叠且不会被强制弹开。
2. **编辑器双引号（引用块）效果回退取消**（“写作里双引号编辑的效果没法回退取消”）：重构富文本编辑器的引用与标题处理逻辑，增加了 `toggleBlockquote` 与 `toggleHeading`，在选中区域已处于引用块 `<blockquote>` 时，再次点击工具栏双引号按钮能够精准回退取消并还原为标准段落 `<p>`。
3. **新建章节去除多余占位文案**（“从这里开始新的篇章……这个东西取消，默认不需要这个”）：移除了新建章节时默认填充的 `"<p>从这里开始新的篇章……</p>"`，新章节初始化为纯净空白段落 `"<p></p>"`。
4. **目录章节字数默认显示为 0 的 Bug 修复**（“当默认章节时，即作品目录里，章节的字数没法正确显示，默认为0，且在你点击进去后，该章节才会统计出正确的字数”）：根本原因在于作品详情接口 `GET /api/works/:workId` 仅在章节摘要中返回 `word_count` 而不带全文 `content`，前端原先用 `plainText(c.content).length` 导致未点击的章节字数全部计算为 0。现全面改用 `c.id === selectedId ? plainText(c.content).length : (c.wordCount ?? 0)`，目录列表与全书总字数均能直接从服务端摘要正确显示。
5. **创建小说目标字数任意值支持**（“创建小说时，设置目标字数有错误，我们保证它能够任意字数也可以创建小说”）：修复了目标字数 `parseInt(targetWords, 10) || 1000000` 导致输入 0 被错误覆盖为 100 万的短路缺陷，放开 HTML5 输入限制为 `min="0" max="20000000"`，支持 0（不设限）、几百、几千或数百万等任意合法目标字数。

## 2. 修改的文件与组件清单

前端严格限定在责任目录内修改：

- `app/page.tsx`
  - 移除对当前卷的自动展开 `useEffect`，允许作者自由折叠包含当前激活章节的卷。
  - 新增 `toggleBlockquote` 与 `toggleHeading` 函数，支持双引号（引用块）和标题格式的开启与回退取消。
  - 工具栏双引号按钮点击绑定为 `toggleBlockquote`。
  - 新建章节 `addChapter` 移除 `从这里开始新的篇章……`，默认正文设为 `"<p></p>"`。
  - 新增 `getChapterWordCount` 函数并应用于目录小角标与总字数 `totalWords` 统计，确保初始加载时所有章节直接显示服务端持久化的真实 `wordCount`。
  - `handleEditorInput` 同步更新本地 state 中的 `wordCount: newWords`。
- `components/workbench/create-work-dialog.tsx`
  - 修复 `targetWords` 解析逻辑，允许 `0` 至 `20,000,000` 的任意合法整数。
  - 更新数字输入框属性为 `min="0" max="20000000" step="1000"`，并增加提示文本说明支持 0（不限）或任意字数。
  - 清理未引用的 `Sparkles` 图标导入。
