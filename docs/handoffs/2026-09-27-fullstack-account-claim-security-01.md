日期：2026-09-27  
方向：Codex → 项目所有者  
结论：**访客作品认领、登录会话管理和账号数据出口已完成首轮交付。** 未执行用户正式数据库的认领、账号注销或数据删除。

## 页面交付

- 新增 `/claim`：登录用户可查看本机 `local-author` 作品摘要，目标邮箱、章节数和字数清晰可见；不在预览接口返回正文。
- 页面必须先下载当前快照的 JSON 备份，确认框和“确认认领”才解锁。备份后数据发生变化会要求重新检查和下载。
- 认领成功显示转入数量并引导返回工作台；入口已加入账号菜单。
- 新增 `/sessions`：展示有效会话的创建、最近活动和到期时间，唯一标出当前设备。其他会话采用“撤销 → 确认撤销”两步操作；当前设备没有撤销按钮。
- 账号菜单新增“登录设备与会话”入口。当前数据模型没有 UA/IP，因此不伪造具体浏览器、设备或地点名称。
- 个人设置页原“完整备份”只是前端构造的少量假数据，现已替换为服务端真实账号导出，并明确排除敏感认证数据。

## 接口、契约与安全边界

- `GET /api/guest-claim/preview`：本机且已登录，只返回访客作品摘要和完整快照摘要。
- `GET /api/guest-claim/backup`：下载完整访客 JSON 备份并签发一小时 HttpOnly、SameSite=Strict 备份凭据；凭据绑定账号、快照和全部作品 ID。备份沿用正式导出，不含 AI API Key。
- `POST /api/guest-claim`：要求同源、`confirm:true`、全部 ID、同一快照及有效备份凭据。单条 SQL 一次性改变全部 `works.owner_id`；卷章、设定、版本、统计和 ID 不复制、不删除。预览变更返回 409，未备份返回 412，重复提交返回 `alreadyClaimed:true`。
- 认领仅开放 localhost / 127.0.0.1 / `[::1]`；正式部署返回 403。账号原有作品保留，访客 AI 配置与工作台偏好不迁移。
- `GET /api/auth/sessions`：列出当前账号未撤销、未过期会话并标明当前会话；读取时清理该账号过期记录。
- `DELETE /api/auth/sessions/:sessionId`：只能撤销当前账号的其他会话；当前会话返回 409，跨账号/不存在返回 404，重复撤销幂等。会话 Cookie 和 token 摘要均不进入响应。
- 已登录请求的 `lastSeenAt` 至多每五分钟更新一次。
- `GET /api/account/export`：下载账号公开资料及该账号的完整正式作品备份；不导出密码、验证码、会话或 AI API Key，使用 `Cache-Control:no-store`。
- 新契约位于 `contracts/guest-claim.ts` 与 `contracts/auth.ts`；详细语义已写入 `docs/API_CONTRACTS.md` 和 `docs/AUTH_API.md`。

- 数据库迁移：无。认领复用既有所有权及外键结构；会话复用既有时间与撤销字段。
