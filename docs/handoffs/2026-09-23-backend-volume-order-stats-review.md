## 2. 分卷排序正式契约

请求：POST /api/works/:workId/volumes/reorder

~~~json
{ "volumeIds": ["当前作品分卷 UUID 2", "当前作品分卷 UUID 1"] }
~~~

示例中的字符串需替换为真实 UUID，不能直接发送。

成功为 HTTP 200，data 是排序后的完整 Volume 数组，包含 id、workId、title、summary、sortOrder、createdAt、updatedAt。

- 列表必须恰好覆盖当前作品所有分卷且无重复，1～500 项；未分卷是 UI 虚拟分组，不提交。
- 400：空列表、重复 UUID、格式错误、超上限；409：不完整/已失效/其他作品分卷；404：作品不存在、归档或不属于当前账号。
- SQL 写入时重新校验完整列表，并在同一事务内更新分卷和作品时间。拒绝请求不部分修改。
- 同一集合并发改序采用最后成功写入结果，不检测“只改了顺序但集合没变”的旧请求。前端完成后可重新拉列表核对，不能宣称实时协作。
- 不改变章节正文、revision、volumeId 或大纲作用范围。GET 作品详情/分卷列表和已有导出使用更新后的分卷顺序。
- 409 后刷新完整列表并提示重试，不自动把旧排序覆盖回去。首次前端采用上移/下移即可，拖拽可另批交付。

章节跨卷移动本轮未新增接口，现有 PATCH /api/chapters/:chapterId 支持 volumeId；复杂移动/全量排序需要另行约定目标位置，不能把本分卷排序接口用于移动章节。

## 3. 统计契约与接入说明

GET /api/works/:workId/stats 和 PUT 同路径继续保留既有字段，新增：

| 字段 | 含义 |
| --- | --- |
| timeZone | 固定 Asia/Shanghai |
| today | 服务端上海日期 YYYY-MM-DD |
| todayWordsWritten | 本作品当天已保存正文的正向字数变化累计，无记录为 0 |
| todayTargetWords | 本作品当天记录中的目标；null 表示没有记录，0 表示不设限 |

TypeScript 正式类型：contracts/types.ts 中 WorkStats / WritingDayStats。

接入规则：

1. 作品切换后按 workId 加载统计，并保护迟到响应。工作台和 StatsView 使用同一作品统计来源。
2. 已保存统计以接口为准；本地实时草稿字数若保留，应单独标为“未保存”，不得与服务端累计相加导致重复。
3. 用 PUT 提交 date（使用服务端 today）和 targetWords。合法目标 0～100000；date 需为真实日历日期，400 保留输入并提示。
4. 当日目标为空时显示“未设置”；0 显示“不设限”，不计算除零进度。第一次正向保存若尚无记录，会按现有逻辑创建目标 3000；这是旧行为，不是永久目标偏好。
5. 连续天数从今日向前计数，今日没有写作记录则为 0。daily 最多 90 条已有日期记录，不必连续；连续天数本身可超过 90。
6. 请求失败时保留上次成功数据并标为未更新或显示重试，不能回退全局 localStorage、固定样例或假图表。
7. 不新增 todayNetWords / recentTrends；本轮不做净增账本，不将正向字数命名为净增。

兼容性：新统计字段为增量增加；旧字段仍在。无效日期从宽松接受改为 400；合法旧请求不受影响。expectedRevision 仍兼容可选字段，未因前端交付声明而贸然改成必填。

## 5. Gemini 下一轮必须处理的具体问题

### F01：创建作品在保存失败后仍切换（P0）

app/page.tsx 的 handleWorkCreated 忽略 flushPendingSave 返回值。更早的 CreateWorkDialog 已经 POST 创建了作品，后端 createWork 会同时改变活动作品偏好。

应在提交创建请求之前完成草稿保存/失败拦截；回调也检查结果，并 await 相关流程。保存失败时不发送创建请求、不自动切走。恢复回收站后的 onRestored 直接重载工作区也需同样审计。不要仅在弹窗成功关闭后增加一个 await。

验证：草稿保存返回 500 或 409，点击创建作品/恢复回收站，当前草稿完整、不会跳到新工作区；允许重试。

### F02：保存与版本恢复的所有入口共享同一版本依据（P0）

confirmedRevisionsRef 会优先于 React state 被普通保存读取，但 handleVersionRestored、handleForceOverwrite 和 handlePullServerVersion 尚未同步它。成功恢复/覆盖后继续输入，可能再次提交旧 revision。

统一更新服务端已确认 revision、保存状态、草稿序号和待保存队列。普通保存返回时 title 仍无条件采用旧响应，应同时保护在途期间的新标题；网络失败且新 pending 只有标题/正文其中之一时，要合并未确认字段，不能丢另一字段。确保 409 后只有用户明确决策才覆盖服务端。

验证：恢复历史后立即编辑、强制覆盖后立即编辑、保存正文期间修改标题、网络失败期间交叉修改标题和正文。

### F03：正文与关联的迟到响应（P0）

loadWorkspaceData、selectChapter、loadChapterLinks 返回时仍会直接更新 state 或编辑器 innerHTML。为工作区、选章、关联分别建立请求代次/当前目标检查；目标变更后不再应用旧响应。切章加载期间应禁止对旧正文进行新章保存，或明确保留安全编辑目标。

验证：A 章请求延迟，切到 B 后 A 返回，B 不显示 A 正文；快速切作品同理；章节关联不得跟着迟到响应串章。

### F04：批量关联失败后期望选择被 effect 覆盖（P1）

ChapterLinksDialog 的 useEffect 依赖 [open, linkedItems]，每次 onLinksChanged 更新服务端事实都会 setSelectedKeys 并 setErrorMessage(null)。分开“服务端事实”和“用户期望选择”；仅首次打开或切换章节初始化选择，刷新事实只用于计算剩余差量。重新获取事实本身失败时提示重新同步，不能无依据继续提交旧差量。

验证：添加成功、移除失败，用户原先勾选仍在，部分完成提示持续可见，重试只发送剩余差量。

### F05：字体规范完成度与 UI 证据（P1）

继续依据 UI_STYLE_GUIDE.md，把字号映射成可复用的语义令牌。至少修正 AI 配置预设按钮及其他实际可点击的 10～12px 字号；普通辅助说明可按规范保留 12px。不要仅做批量字符串替换或把所有文字放大成同一号。

提交工作台、AI 配置、复杂弹窗、登录/个人中心的真实截图，验证三种桌面尺寸、125%/150% 缩放、右栏打开/折叠、长文滚动和键盘。功能校验与视觉验收分别记录。
