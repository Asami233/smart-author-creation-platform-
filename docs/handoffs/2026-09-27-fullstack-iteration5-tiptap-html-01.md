## 产品决定与兼容性

用 TipTap 替换工作台原生 `contentEditable`，但本批**继续使用既有 HTML v1 正文格式**，不引入 TipTap JSON v2 或批量重写旧稿。旧 API、旧章节和备份可继续读取；编辑器对旧 HTML 的不支持标签可能规范化，因此首次 TipTap 正文保存显式请求保存服务器原稿快照，作者可在历史版本中找回原文。标题等非正文改动不触发该快照。每章在当前浏览器会话内最多主动请求一次保护快照；未来应进一步评估跨会话标记及完全无损转换。

## 分层交付

- 前端：`app/page.tsx` 接入 TipTap StarterKit，保留二级标题、加粗、斜体、引用、列表、撤销/重做。编辑器实例随章节切换重建，避免撤销跨章。正文继续走原防抖保存、修订冲突及离开门禁。AI 采纳构造文本节点而非解析模型输出 HTML；剪贴板只插入纯文本。`app/globals.css` 维持网文排版及空段落提示。
- 字数：新增 `lib/client/chapter-text.ts`，解码 HTML 实体并按 Unicode 字符计数，使客户端正文/目录字数更接近服务端口径，避免 TipTap 转义文字后显示虚高。历史文本转 HTML 时先做转义。
- 契约/API：`PATCH /api/chapters/:chapterId` 新增可选 `preservePreviousVersion: true`。若正文实际变化，服务端在本次受修订保护的写入前强制保存旧正文版本；与 `saveId` 重试幂等兼容。未传该字段的旧客户端维持原阈值快照规则。详见 [API 契约](../API_CONTRACTS.md)。
- 数据库：**无新迁移**；沿用第七天的 `contentFormatVersion: 1` 与 `drizzle/0005`。部署或日常数据库使用前仍须按正常流程先备份并应用既有未执行迁移。
- 共享文件：仅为编辑器接入添加 `@tiptap/react`、`@tiptap/pm` 和 `@tiptap/starter-kit` 3.31.3，修改 `package.json`/`package-lock.json`；不改变构建方式，不升级其他依赖。

## 后续门槛

- TipTap 替换不等于迭代 5 完工：查找替换、专注模式、章节跳转、10 万字浏览器编辑性能、断网/多浏览器回归仍未验收。
