# 前后端协作与代码所有权规则

## 1. 目的

本规则最初用于 Codex 与 Gemini 并行开发。自 2026-09-26 起，项目所有者授权 Codex 单人负责前端、后端、契约、测试与联调，核心原则调整为：

- 前后端仍通过稳定契约协作，即使由同一负责人实现。
- 修改现有脏工作树时保留既有成果，只提交当前目标所需的最小改动。
- 每个工作包同时记录页面、接口、数据和验收影响。
- 隐私、安全和数据完整性优先于开发速度。

## 2. 角色与职责

### Codex：全栈负责人

负责：

- 页面信息架构与视觉呈现
- 桌面端响应式布局
- 富文本编辑器交互
- 章节树、侧栏、弹窗和前端状态
- 加载、空状态、错误状态和成功反馈
- 无障碍、键盘操作和前端测试
- 按已确认 API 契约完成接口调用
- API 设计与实现
- 作品、卷、章、大纲、角色、世界观和时间线的数据模型
- 本地持久化层及未来云端数据库演进
- 历史版本、自动快照和恢复逻辑
- TXT、DOCX、PDF 导出服务
- 登录、会话、鉴权与数据隔离
- OpenAI-compatible AI 服务端适配层
- 上下文范围控制、密钥保护、限流、重试和错误映射
- 后端测试、数据库迁移和接口文档
- 前后端联合验收与交付文档

## 3. 目录所有权

| 路径 | 所有者 | 说明 |
| --- | --- | --- |
| `app/api/**`、`server/**`、`db/**`、`drizzle/**`、`lib/server/**` | Codex | 服务端、数据与安全逻辑 |
| `contracts/**` | Codex | 前后端共享的正式契约 |
| `app/**`（排除 `app/api/**`）、`components/**`、`hooks/**`、`lib/client/**`、`public/**` | Codex | 页面、交互和客户端接入 |
| `tests/backend/**`、`tests/frontend/**` | Codex | 分层自动化测试 |

## 4. 共享文件管理

共享文件包括依赖清单、构建配置、项目说明和环境变量示例。修改流程为：

1. 说明为什么必须修改及影响范围。
2. 由 Codex 执行最小修改。
3. 在交付说明中单独列出共享文件变更。
4. 不因格式化、清理或个人偏好改写共享文件。

依赖安装遵循以下规则：

- 前后端依赖均由 Codex 按任务需要提出并修改。
- 会改变构建方式或运行环境的依赖，需要项目所有者确认。
- 不做无关版本升级，不批量清理现有依赖。

## 5. API 契约流程

正式接口定义放在 `contracts/**`，说明文档放在 `docs/API_CONTRACTS.md`。一个接口至少要包含：

- 方法与路径
- 用途和权限要求
- 请求参数与请求体
- 成功响应
- 可预期错误与状态码
- 是否会修改数据
- 隐私与敏感字段说明

协作流程：

1. 先从用户流程定义页面需要的数据和交互场景。
2. 在 `contracts/**` 设计或更新接口，再实现服务端。
3. 前端只基于正式契约接入，不依赖数据库内部结构。
4. 需要变更时优先保持向后兼容；破坏性变更必须明确标记并补迁移说明。

## 6. Mock 数据规则

前端允许在后端完成前使用 mock，但必须满足：

- 只放在前端责任区，例如 `lib/client/mocks/**`。
- 文件顶部标记 `MOCK_ONLY`。
- 字段结构与当前契约保持一致。
- 不包含真实 API Key、账号、作品或个人信息。
- 接入正式接口后删除对应 mock，不能在生产路径静默回退到假数据。

## 7. AI 与隐私红线

- 模型 API Key 只能由服务端读取。
- 前端不得直接请求模型供应商。
- 默认不向模型发送整部作品。
- 每次 AI 请求必须由用户主动触发，并明确展示参考范围。
- AI 输出先预览，未经用户确认不得覆盖正文。
- 日志不得记录 API Key、完整正文或其他敏感内容。

## 8. Git 工作方式

建议使用 `codex/<topic>` 分支。每次提交只包含当前工作包所需的改动。合并前检查：

1. 是否覆盖了项目所有者已有的未提交改动。
2. 是否修改共享文件但没有说明。
3. 接口契约是否与实现一致。
4. 是否包含密钥、构建产物或本地数据。
5. 前端测试、后端测试、类型检查、构建与真实页面验收是否按风险完成。

## 9. 冲突与例外

出现以下情况时停止修改并交给项目所有者决定：

- 接口需求会明显改变产品交互。
- 需要覆盖来源不明或正在进行中的用户改动。
- 需要引入会影响整个项目的新框架或基础设施。

项目所有者可调整负责人或范围；发生调整时先更新本文件与 `AGENTS.md`，再继续开发。
